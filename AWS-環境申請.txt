【專案需求】純前端靜態網站（SPA）AWS 託管環境申請

一、系統架構與技術型態

1. 應用類型：純前端單頁應用程式（Static SPA），建置產物只有 HTML、CSS、JS 與字型圖片等靜態資源。
2. 後端與資料庫：本系統沒有自建後端，無需 EC2、ECS、Lambda、RDS 或 API Gateway。
3. 資料來源：瀏覽器直接連線 Google Firebase Firestore（既有服務，非本次申請範圍）。
4. 身分驗證：無，沒有 Cognito、沒有 OAuth、沒有伺服器端 session。
5. 機密管理：無，前端不含任何伺服器端金鑰或 secrets。

補充說明：學員姓名、手機、學習進度等資料存放於 Firebase（Google Cloud），不在 AWS。
若公司對個資存放地有規範，請一併由資安或法務確認。本申請僅涵蓋網站託管。

二、所需 AWS 資源

1. Amazon S3
   用途：存放前端建置產物
   設定：私有 bucket，開啟 Block all public access
   備註：不需要開啟 S3 靜態網站託管功能（該端點只支援 HTTP，沒有 HTTPS）

2. Amazon CloudFront
   用途：CDN 與 HTTPS
   設定：1 個 distribution，以 OAC（Origin Access Control）讀取上述 S3 bucket
   備註：不使用公開 bucket，也不使用舊式 OAI

3. AWS Certificate Manager
   用途：HTTPS 憑證
   設定：憑證必須建立於 us-east-1（CloudFront 的硬性要求，其他區域的憑證無法選用）

4. Route 53 或公司 DNS
   用途：子網域指向 CloudFront
   設定：例如 learn.公司網域

5. AWS WAF（選配）
   用途：依公司資安規範掛載既有規則
   備註：純內部使用可省略，對外開放建議掛載

三、路由說明（與一般 SPA 不同，請勿套用通用設定）

本系統使用 hash 路由，網址形如 網域/#/c/courseId，路徑不會送到伺服器。

1. 不需要設定 CloudFront Custom Error Responses 將 403 或 404 導向 index.html。
2. 若設定該規則，會把「資產 404」與「OAC 設定錯誤造成的 403」都變成 200 首頁，導致問題難以排查。
3. 若未來改用 History 路由，再另行申請調整。

四、快取策略（必要）

1. index.html：Cache-Control 設為 no-cache, no-store, must-revalidate
2. assets 目錄下檔案（檔名含 hash）：Cache-Control 設為 public, max-age=31536000, immutable
3. 若 index.html 被 CDN 長快取，改版後使用者會停留在舊版。

五、網域與資安

1. 強制 HTTPS：CloudFront 設定 Redirect HTTP to HTTPS
2. 建議回應標頭：HSTS、X-Content-Type-Options: nosniff（可用 CloudFront Response Headers Policy）
3. WAF：若為對外服務，建議掛載公司既有規則

六、對外連線需求

網站會在瀏覽器端載入以下外部網域，若公司有 egress 代理、CSP 或防火牆白名單，請一併放行：

1. 資料庫：firestore.googleapis.com（googleapis.com）
2. 字型：fonts.googleapis.com、fonts.gstatic.com
3. 影片（YouTube）：www.youtube.com
4. 影片（Vimeo）：player.vimeo.com、i.vimeocdn.com

若公司要求設定 CSP，需要允許上述來源的 script-src、frame-src、connect-src、font-src。

七、部署與權限交付

現況說明（請據此設計權限）：程式碼目前位於開發者的個人 GitHub repo，公司不建議連結。
因此短期採手動本機部署（開發者建置後上傳），不是 CI/CD 自動化流程。

需要的 IAM 權限（建議以單一 deployment user 或 role，範圍限縮到指定資源）：

1. s3:ListBucket（aws s3 sync 需要列舉 bucket 內容才能比對與刪除多餘檔案）
2. s3:PutObject
3. s3:DeleteObject
4. cloudfront:CreateInvalidation
5. cloudfront:GetInvalidation

資源範圍：

1. S3：僅限指定 bucket（arn:aws:s3:::buke-app-web 與 arn:aws:s3:::buke-app-web/*）
2. CloudFront：僅限該 distribution ARN

不需要 AWS Console 操作權限。

中長期建議：將 repo 轉移至公司 GitHub 組織，之後可改為 GitHub Actions 搭配 OIDC，免長期金鑰自動部署。

八、費用預估

靜態檔案加少量流量（每月數 GB 以內），約 USD 1 至 3 元（S3 儲存、CloudFront 流量、invalidation）。
WAF 另計，約 USD 5 至 10 元起。

九、驗收項目

1. https://learn.公司網域/ 可開啟，HTTPS 正常
2. 課程列表載入（代表 Firestore 連線成功）
3. 進入課程，影片播放、段落跳轉、答題正常
4. 後台 網域/#/admin 登入正常
5. Vimeo 課程可播放（需同時在 Vimeo 後台將此網域加入允許清單）

十、交付清單

1. S3 bucket 名稱
2. CloudFront distribution ID 與網域
3. 子網域與 DNS 設定完成
4. ACM 憑證狀態 Issued（us-east-1）
5. deployment 憑證（access key 或 SSO profile）
6. 是否掛載 WAF、是否啟用 access log

（備註）Vimeo 允許嵌入網域：除了正式網域，建議一併加入 localhost:5173，否則開發階段無法測試 Vimeo 課程。
