# 補課系統（buke-app）

影片分段＋段落檢核的補課系統。學員看完一段影片、答對題目才解鎖下一段；名單分區匯入，補課記錄依區域匯出。

- 前端：Vite + React 18 + TypeScript
- 影片：YouTube 內嵌（需為「公開」或「不公開」）
- 資料庫：Firebase Firestore（**不使用 Firebase Auth**）
- 部署：GitHub Pages（`npm run deploy`）
- 網站：<https://krad1985.github.io/buke-app/>
- repo：<https://github.com/krad1985/buke-app>（public，branch `master`）

## 三種身分

| 身分 | 登入方式 | 權限 |
| --- | --- | --- |
| 學員 | 輸入手機號碼 | 上課、看自己的進度 |
| 課程管理員 | 帳號＋密碼（預設帳號 `admin`） | 課程與題庫、管理員帳號、任何區域的名單與記錄 |
| 區域管理員 | 帳號＋密碼 | 只能匯入自己區域的名單、匯出自己區域的記錄 |

管理員帳號全部由課程管理員在後台建立（「管理員」頁），不需要進 Firebase Console 建帳號，也不需要啟用任何登入方式。

## 第一次上線

**唯一需要的動作：到 Firestore → 規則，貼上 `firestore.rules` 全文並發布。**

沒貼的話，學生端可以正常上課（讀寫本來就開放），但管理後台會因為舊規則而無法登入或儲存。

貼好之後開 `/#/admin`，用 `admin` 登入（初始密碼定義在 `src/lib/admins.ts`，登入後請立刻改掉），然後：

1. 「我的密碼」改掉預設密碼
2. 「課程管理」建立課程（或載入示範課程）
3. 「管理員」建立各區的區域管理員

## 開發

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run deploy   # 推到 gh-pages 分支
```

路由（hash）：

```
/                 學員首頁（未輸入電話會先跳到電話頁）
/#/c/<courseId>   上課畫面
/#/admin          管理後台
```

QA：網址加 `?qa=1` 會多一顆「跳結尾」按鈕。

## 資料結構

```
courses/{courseId}                                        課程（含段落與題目）
admins/{帳號}                                            管理員（含明文密碼）
phones/{電話}                                            電話 → 區域索引
regions/{區域}                                           區域
regions/{區域}/students/{電話}                           學員名單
regions/{區域}/students/{電話}/progress/{courseId}       補課進度
```

名單與進度用**路徑分區**（`regions/{區域}/...`）而不是欄位過濾，因為規則看得到路徑、看不到查詢條件。這樣區域管理員的畫面只需讀自己那條路徑。

## 匯入名單

區域是固定清單：

```
北區　桃區　竹區　中區　園區　嘉區　南區　高區　國際
```

「學員名單」頁選好區域後按**「下載空白範本」**，會得到帶表頭的 CSV：

```
uid,區域,教室,組別,身份,姓名,電話
```

填好後可整塊貼到文字框，或另存 CSV 用「選擇檔案」。

- 電話只留數字，`+886` 轉成 `0` 開頭；格式不對的列會列出來，不會匯入
- 區域欄可留空，一律以頁面選的區域為準
- 同電話重匯＝覆蓋（要改某位學員就重匯那一列）

## 匯出補課記錄

一人一列、各課程一欄的總表：

```
區域, uid, 教室, 組別, 身份, 姓名, 電話,
<課程A>, <課程B>, …, 完課數, 已補時數(分), 最後更新
```

`✓` 已完課、`3/5` 已通過 3 段、空白表示沒紀錄。可勾「只列有紀錄的學員」。檔案帶 BOM，Excel 直接開不亂碼。

## 補課時數

時數 = **已通過段落的影片長度加總**，不是播放秒數（重看、暫停不重複累計）。

- 學員端：課程卡片與課程頁顯示「已補 X 小時 Y 分」
- 報表：「已補時數(分)」整數欄，Excel 可直接加總
- 舊資料沒有 `watchedSec` 時，用 `passed` 對照段落長度即時換算
- 段落時間碼日後調整，已記錄的時數不會回溯改變

## 安全模型（請務必了解）

這是**防君子**設計，內部使用、方便優先：

- **沒有伺服器端的身分驗證。** 管理員密碼以明文存在 `admins/{帳號}`，前端讀出來比對，所以任何能開網站的人（包含學員）都可以用開發者工具直接讀寫資料庫，包含修改或刪除課程。
- 兩層管理員（課程／區域）**只防操作失誤，不防有心人**。
- 唯一還留著的限制：`phones` 不允許列舉（要知道完整號碼才查得到一筆），但 `regions/{區域}/students` 必須開放列舉，所以全區名單理論上可被下載。
- 因為 repo 是 public，程式碼與上述事實都是公開的。

降低風險的做法（已內建）：

- 「課程管理」頁有**匯出備份／匯入備份**（JSON）。做大改動前先匯出，出事可以還原。
- 管理員頁看得到所有人的密碼，忘記就改一組新的。

若要真正的防護，唯一辦法是把管理員的寫入改由伺服器執行（Vercel Function 或 Cloud Functions + Firebase Admin SDK，規則收成 `allow write: if false`）。

## 已知限制

1. 同一個電話只能對應一位學員（共用門號目前不處理）。
2. 進度報表是逐位學員讀取，一區數百人時會慢一點（分批並行）。
3. 影片要「只聽不看」或更嚴格的跳轉限制，需改自架 HLS，YouTube 來源做不到。

`src/data/mockCourses.ts` 只作為「載入示範課程」的種子資料。
