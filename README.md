# 補課系統（buke-app）

影片分段＋段落檢核。看完一段、答對題目才解鎖下一段；名單分區匯入，補課記錄依區域匯出。

- 前端：Vite + React 18 + TypeScript
- 影片：YouTube 內嵌（公開或不公開）
- 資料庫：Firebase Firestore（不使用 Firebase Auth）
- 部署：GitHub Pages ｜ <https://krad1985.github.io/buke-app/>

## 身分

| 身分 | 登入 | 備註 |
| --- | --- | --- |
| 學員 | 學員代碼（例 `TW00103698`） | 不需要密碼 |
| 管理員 | 全站一組密碼 | 所有人共用；進來後可操作所有區域 |

管理密碼存在 `config/admin`，預設 `admin`，在「管理密碼」頁修改。資料庫不分辨誰是管理員。

## 上線設定

Firestore → 規則，貼上 `firestore.rules` 全文（就這麼一行）：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} { allow read, write: if true; }
  }
}
```

沒有其他設定。不需要啟用任何 Firebase 登入方式。

## 開發

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run deploy   # 推到 gh-pages
```

路由：`/` 學員首頁、`/#/c/<courseId>` 上課、`/#/admin` 後台。
QA：網址加 `?qa=1` 會多一顆「跳結尾」。

## 資料結構

```
courses/{courseId}                                      課程（含段落與題目）
config/admin                                            管理密碼
ids/{學員代碼}                                          代碼 → 區域索引
regions/{區域}/students/{學員代碼}                      學員名單
regions/{區域}/students/{學員代碼}/progress/{courseId}  補課進度
```

## 匯入名單

「學員名單」頁選區域 → 上傳檔案（或拖曳、或貼上）。

**直接支援系統匯出的「學員名單查詢結果」xlsx**，欄位對應：

| 匯出檔欄位 | 系統欄位 |
| --- | --- |
| 學員代碼 | 學員代碼（文件 ID） |
| 學員姓名 | 姓名 |
| 母班行政組織 | 母班 |
| 大組 + 小組 | 組別（`1-1`） |
| 身份別 | 身份 |

其他欄位（出席率、善行完成率、問卷回饋率…）忽略。沒有學員代碼的列會列出來，不匯入。同代碼重匯＝覆蓋。

區域由頁面上選的為準，檔案裡的「母班行政組織」不會自動對應到區域。

## 匯出補課記錄

一人一列、各課程一欄：

```
區域, 學員代碼, 母班, 組別, 身份, 姓名,
<課程A>, <課程B>, …, 完課數, 已補時數(分), 最後更新
```

`✓` 完課、`3/5` 已通過 3 段、空白表示沒紀錄。可勾「只列有紀錄的學員」。

## 補課時數

已通過段落的影片長度加總（重看、暫停不重複累計）。段落時間碼日後調整，已記錄的時數不會回溯。

## 播放器

- `controls=0` 關掉 YouTube 原生控制列
- 全尺寸透明遮罩攔掉所有點擊（標題、Logo、「在 YouTube 觀看」都點不到）
- 自訂控制列：播放/暫停、段落內時間軸、倍速、全螢幕、重看本段
- 全螢幕只包住播放器與控制列；進入答題時會自動退出全螢幕

時間軸刻意限制在「目前段落」範圍內，這是分段解鎖的核心，不是功能缺失。

> 注意：遮蔽 YouTube 品牌與外連違反 YouTube API 服務條款的風險由使用者承擔；官方若改版，`controls=0` 的實際效果可能改變。

## 安全模型（請務必了解）

- 沒有任何伺服器端驗證。資料庫全開，任何人開 devtools 都能讀寫，包含讀到管理密碼、刪除課程。
- 管理密碼只是畫面上的門；它不保護資料，只避免誤闖。
- 課名單分區是為了「操作方便」，不是權限隔離——拿到密碼的人可以切換任何區域。

降低風險的既有做法：課程管理頁有**匯出備份／匯入備份**（JSON），大改動前先備份。

## 已知限制

1. 匯出檔沒有電話欄位，因此改用學員代碼登入。
2. 報表逐位學員讀取，一區數百人會慢一點。
3. 影片要「只聽不看」需自架 HLS，YouTube 做不到。

`src/data/mockCourses.ts` 只是「載入示範課程」的種子資料。
